2.2

ユーザー向け

  • 過去の会話を「いつ・誰と・何について話したか」から、より正確に探せるようになりました。「最近」「今月」「一番最近」などの時期指定にも対応しています。
  • 直前の返答に出た話題を踏まえ、続きの質問でも対象の会話と前後のやり取りを確認して答えるようになりました。
  • 同じ内容を聞き直したとき、説明を最初から繰り返しにくくなりました。追加の質問には、聞かれた部分や新しく分かった内容を中心に答えます。
  • 「私」「ワイ」など、自分を指す言い方を利用者に合わせて扱えるようになりました。質問者本人への呼称は原則「あなた」とし、引用や記録上の名前は保持します。
  • 分からないことを推測で埋めず、必要なことだけ短く聞き返すようになりました。記録を取得できない場合も、確認できないことを短く伝えます。
  • 現在の日付・時刻・曜日を聞く質問には、日本時間で答えるようになりました。
  • 実際に交わした会話を聞く質問では、WhatsAppの会話記録を確認して答えるようになりました。
  • 回答処理の無駄を減らし、一部の検索や続きの質問で待ち時間を短縮しました。
  • 入力中に改行でき、長い文章も書きやすくなりました。返答本文のコピーと、返答詳細をまとめたコピーを使い分けられます。
  • ダークモードや、入力欄に表示される言葉の切り替えに対応しました。リリースノートも変更内容をまとめて読めるようになりました。

DEV

  • temporal検索をconversation_dateベースで実装し、対象期間のMESSAGES原文に基づいて回答を生成します。
  • 通常のsemantic検索と、期間で絞ってから意味検索するtemporal_then_semanticを分離しました。
  • WhatsApp原文はdirect_conversation専用経路で処理し、前後の文脈とともに参照します。
  • contextual follow-upでは直前回答を参照先の特定にだけ使い、事実確認は原文を再検索します。独立した質問には不要な会話履歴を渡しません。
  • 一人称の自己参照を利用者情報から解決し、内部人物同定と最終回答の呼称を分離しました。引用や話者名を保持し、本人参照は「あなた」と表示します。
  • same_answer / subset / superset / related_but_different / new_topicの5分類で回答重複を制御し、直前Q&Aを優先します。
  • clarification / no_evidence / evidence_errorを分離し、意図の曖昧さ・情報不足・取得失敗を区別して応答します。
  • 一意なcontext anchorに一致する原文と必要な周辺だけを優先取得します。一致がない場合は通常検索へ戻ります。
  • 不要な回答比較モデルの呼び出しを事前判定でスキップし、検索クエリへの期間・人物・話題の重複追加を抑えました。
  • 現在日時の質問はapp_metaをtemporal検索より優先し、会話検索や回答生成モデルを呼ばずに処理します。
  • TESTログの保存・診断参照をTESTQA_LOGへ分離し、検索・回答・取得エラーの診断をまとめて記録します。
  • 本番回答経路と本番QA_LOGの保存先を維持し、検索・回答の変更はTEST経路に限定しています。
